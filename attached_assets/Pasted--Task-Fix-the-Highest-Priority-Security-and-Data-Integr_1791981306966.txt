# Task: Fix the Highest-Priority Security and Data-Integrity Issues

Work only on the current **Jusoor Entrepreneurship Program System** project. Treat this as the new project and do not rely on previous projects or their test results. Ignore Calendly OAuth completely.

## Objective

Address the three highest-priority findings from the read-only audit:

1. Participant live-session API router is mounted without the expected authentication middleware.
2. Program staff permissions are not restricted by program assignment.
3. Program deletion can cascade into permanent data loss.

## 1. Participant session authentication

- Inspect the production application router composition and the live-session interaction routes.
- Apply the correct participant authentication middleware at the actual application mount.
- Ensure the handler's participant identity comes from trusted server-side authentication, not client-supplied identity fields.
- Preserve accepted-enrollment and program-scope checks.
- Add tests against the real application router for unauthenticated requests, accepted participants, unaccepted participants, and cross-program access.
- Do not rely solely on tests that inject a test-only identity middleware directly into the handler.

## 2. Program-level staff authorization

- Define the intended access rules for coordinator and program staff.
- Coordinators may retain global access if that matches the intended operating model.
- Program staff must be restricted to explicitly assigned programs unless a documented business requirement establishes otherwise.
- Enforce authorization on every relevant list, read, create, update, and delete operation.
- Apply scope restrictions in database queries and mutation checks, not only in UI navigation.
- Default to denying access when program assignment or scope cannot be established.
- Add cross-program denial tests for each affected operation.

## 3. Safe program archival and deletion

- Prefer an archive/deactivate workflow over hard deletion.
- Ensure archived programs are hidden from active operational views but remain available for authorized historical reporting.
- Prevent accidental cascading deletion of applications, businesses, courses, participants, evaluations, and related records.
- If hard deletion remains necessary, require an explicit, authorized process with an impact preview, confirmation, and a documented retention policy.
- Preserve audit history.
- Add tests that verify archival preserves related records and that unauthorized or accidental deletion is rejected.

## Safety and implementation constraints

- Inspect existing code and test scripts before changing anything.
- Do not access production or connect to any existing database.
- Do not run migrations against any existing database.
- Do not send email or call external providers.
- Do not publish or deploy.
- Do not weaken authentication or authorization to make tests pass.
- Avoid unrelated refactoring and feature additions.

## Verification and reporting

- Add focused automated tests for every fix.
- Run only tests that are safe and appropriately isolated.
- Report the exact tests run and their observed results.
- Distinguish source changes and unit-test evidence from database integration or browser verification.
- Update the project QA documentation with the findings, fixes, residual risks, and any checks that could not be verified.
- Stop after these three areas are addressed. Do not begin the lower-priority audit items in this task.
