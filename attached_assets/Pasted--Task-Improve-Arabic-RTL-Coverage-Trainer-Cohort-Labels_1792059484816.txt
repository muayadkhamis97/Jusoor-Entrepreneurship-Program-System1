# Task: Improve Arabic/RTL Coverage, Trainer Cohort Labels, and Text Readability

**Project:** Jusoor Entrepreneurship Program System  
**Re-audit reference:** `docs/UX_UI_PLATFORM_REAUDIT.md`  
**Original audit:** `docs/UX_UI_PLATFORM_AUDIT.md`

## Objective

Implement the next focused batch of UX/UI improvements based on the re-audit findings.

Address these three areas:
1. Arabic translations and RTL layout coverage.
2. Meaningful trainer program and cohort labels.
3. Readability of small functional text and metadata.

Inspect the current implementation before making changes. Use the re-audit findings and their IDs as the source of truth. Preserve existing business logic, role permissions, program assignments, and data integrity.

## 1. Arabic Translations and RTL Coverage

Review the Arabic and English experience across the important user-facing workflows, prioritizing applicants, participants, coordinators, and trainers.

### Requirements

- Identify untranslated or partially translated interface sections.
- Add missing Arabic translations using the existing localization conventions.
- Review navigation, page titles, buttons, forms, validation messages, dialogs, tables, dashboards, empty states, notifications, and error messages.
- Ensure the correct document language and text direction are applied when switching languages.
- Fix RTL-specific alignment, spacing, layout mirroring, directional icons, and navigation behavior.
- Handle mixed Arabic and English text, numbers, dates, and currencies without introducing layout problems.
- Preserve proper nouns, user-generated content, dynamic values, and intentional exceptions.
- Keep English LTR layouts and existing translations intact.

### Translation quality

Use natural, professional Arabic suitable for an entrepreneurship program management platform. Maintain consistent terminology across roles and workflows. Avoid literal translations that make labels confusing or unnecessarily long.

### Automated verification

- Add or improve a translation-completeness check for important interface strings.
- Ensure missing translations are detected without incorrectly flagging intentional exceptions or dynamic content.
- Add tests for language switching and RTL-related behavior where the existing test framework supports them.
- Run existing localization tests and relevant application tests.

Do not claim that Arabic visual rendering is verified unless Arabic pages have actually been rendered and inspected in a browser.

## 2. Replace Numeric Trainer Cohort Labels

Review the trainer interface and identify the numeric cohort labels highlighted in the re-audit.

### Requirements

- Display meaningful program names, cohort names, or other appropriate labels supported by the existing application data.
- Reuse existing program and cohort relationships rather than inventing labels or duplicating data.
- Keep labels consistent with the names displayed in coordinator and program-management interfaces.
- Ensure trainers can distinguish between multiple assigned programs or cohorts.
- Provide a clear fallback for missing or unavailable names without displaying misleading information.
- Check both desktop and mobile layouts, including long program names and Arabic RTL labels.
- Preserve program-scoped access controls and existing trainer permissions.

Do not change database schemas or add migrations merely to improve presentation. If the existing data model does not provide enough information to display meaningful labels, document the limitation rather than fabricating names.

Add or update tests for label selection, missing names, multiple assigned cohorts, and role-scoped visibility where practical.

## 3. Improve Text Readability

Review shared design tokens and components responsible for small functional text, especially labels and metadata.

### Requirements

- Identify text that is unnecessarily small or difficult to read.
- Improve typography for form labels, helper text, table metadata, dashboard summaries, status information, secondary text, and navigation labels.
- Establish consistent font sizes, line heights, and hierarchy across pages.
- Maintain sufficient contrast between text and backgrounds.
- Preserve readable layouts for dense tables, analytics dashboards, and administrative workflows.
- Ensure text remains legible at mobile widths and when users zoom in.
- Prevent Arabic text clipping, overlapping, and awkward line wrapping.
- Avoid indiscriminately increasing every font size or causing new overflow problems.

Prefer shared design tokens and reusable components so improvements remain consistent across the platform.

Where feasible, verify text contrast against WCAG 2.2 AA requirements: 4.5:1 for normal text and 3:1 for large text.

Add appropriate automated checks or tests where supported. Document any contrast or visual checks that require manual browser inspection.

## 4. Scope and Regression Prevention

Before implementing changes:

- Read both audit reports.
- Identify the exact findings related to these three areas.
- Inspect the affected components, localization files, design tokens, and existing tests.
- Establish a checklist of the specific issues being addressed.

During implementation:

- Fix shared root causes where practical.
- Avoid unrelated refactoring or redesign.
- Preserve current workflows, routes, authentication, authorization, and program assignments.
- Do not remove functionality to simplify the interface.
- Do not introduce new dependencies unless genuinely necessary and justified.

After implementation, check the affected routes and shared components for regressions.
